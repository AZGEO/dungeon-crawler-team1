# Screenshot and Demonstration Guide

## Purpose
The instructor asks for screenshots in step-by-step / logical order, including the process of opening and using the program. Include instructions. Test-case screenshots must be collected into one PDF or placed inside the ZIP folder.

## Capture screenshots in this order
Use the sequence below as a general evidence structure. Adjust it to match the actual program.

1. **Project files** — show the project folder and the Java source folder.
2. **Opening the project** — show the project opened in the IDE or the required Java environment.
3. **Starting the program** — show the program being run.
4. **Initial screen** — show the first screen or prompt.
5. **Normal use** — show the main user interaction in logical order.
6. **Feature demonstrations** — capture each major implemented feature.
7. **Decision examples** — capture meaningful choices or branches, if applicable.
8. **Repeated interaction** — show the repeat/continue behavior, if applicable.
9. **Test cases** — capture representative valid, boundary, and invalid-input tests where relevant.
10. **Completion** — show the intended ending, result, or exit.
11. **Final successful run** — show that the program completes without a visible error.

Only include steps that apply to the finished project. Do not fabricate screenshots or present unimplemented features as working.

## Screenshot quality
- Keep the program output readable.
- Include enough of the application window to show context.
- Avoid covering important output with menus or notifications.
- Use a consistent naming order, for example:
  - `01-project-folder.png`
  - `02-java-source.png`
  - `03-program-start.png`
  - `04-initial-screen.png`
  - `05-test-tc01.png`
- Make sure screenshots are genuine captures of the group's program.

## Test-case PDF
Combine test screenshots into one clearly ordered PDF. Add a short caption for each image:
- Test case ID
- What was entered or done
- Expected result
- Actual result
- Pass / Fail

## User instructions
Write the final user guide only after the project flow and controls are settled. It should explain:
1. How to open or launch the program.
2. What the user sees first.
3. How to make a selection or enter information.
4. How to move through the program.
5. How to repeat an interaction, if supported.
6. How to finish or exit.

Replace these general steps with instructions that accurately match the finished program.
