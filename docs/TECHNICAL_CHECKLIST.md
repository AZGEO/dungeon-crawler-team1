# Java Technical Requirements Checklist

Use this checklist while developing and reviewing the program. The assignment specifically requires input/output, correct data types, repetition, selection statements, and arrays.

## 1. Input and output
- [ ] The program accepts user input where needed.
- [ ] Prompts explain what the user should enter.
- [ ] Output is readable and clearly identifies results or program status.
- [ ] Invalid or unexpected input is handled appropriately.
- [ ] The program communicates how the user can proceed or exit.

Possible Java tools: `Scanner`, `System.out.print()`, and `System.out.println()`.

## 2. Data types
- [ ] Each variable uses an appropriate data type.
- [ ] Numeric values are not unnecessarily stored as text.
- [ ] Text values use `String` where appropriate.
- [ ] Boolean values use `boolean` where appropriate.
- [ ] Array element types match the values stored in them.
- [ ] Conversions are handled safely when needed.

## 3. Repetition / loops
- [ ] At least one appropriate loop is used.
- [ ] Repetition has a clear stopping condition.
- [ ] The user can repeat relevant interactions if the project requires it.
- [ ] Loops do not run indefinitely by mistake.
- [ ] Loop boundaries are tested.

Possible Java tools: `for`, `while`, and `do-while`.

## 4. Selection statements
- [ ] The program makes decisions based on conditions or user choices.
- [ ] All expected branches have been considered.
- [ ] A default or invalid-choice path is provided where appropriate.
- [ ] Conditions are logically correct.

Possible Java tools: `if`, `else if`, `else`, and `switch`.

## 5. Arrays
- [ ] At least one array is meaningfully used.
- [ ] Array size and indexing are handled correctly.
- [ ] Values are stored in and retrieved from the array as intended.
- [ ] Loops do not access indexes outside the array's bounds.
- [ ] Empty or unused positions are handled appropriately, if applicable.

## 6. Final code review
- [ ] Source code compiles without errors.
- [ ] Class and variable names are understandable.
- [ ] Indentation and formatting are consistent.
- [ ] Repeated code is reduced where practical.
- [ ] Comments explain non-obvious logic rather than every line.
- [ ] No unfinished sections, accidental debug output, or obsolete code remain.
