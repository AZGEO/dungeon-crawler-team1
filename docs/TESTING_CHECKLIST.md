# Testing Plan and Test-Case Record

## Purpose
Test the completed Java program before submission. The instructor's instructions require screenshots of test cases, collected into one PDF or included in the ZIP folder.

## General testing checklist
- [ ] Program launches successfully.
- [ ] Main screen or starting interaction appears correctly.
- [ ] Each implemented feature is tested.
- [ ] Expected user inputs produce expected results.
- [ ] Invalid inputs are handled appropriately.
- [ ] Each important selection/decision path is tested.
- [ ] Repetition and exit behavior are tested.
- [ ] Array-related behavior is tested.
- [ ] Program can complete a normal run without crashing.
- [ ] Program can be restarted and tested again.

## Suggested test coverage
Choose cases that match the features actually implemented. Do not claim a feature has passed if it has not been tested.

- **Normal input:** a typical valid user entry.
- **Boundary input:** the smallest/largest or edge value relevant to the feature.
- **Invalid input:** an entry the program should reject or handle safely.
- **Decision paths:** test each meaningful branch or menu choice.
- **Repetition:** repeat an action and verify the loop behaves correctly.
- **Array behavior:** verify stored values and valid index access.
- **Completion:** verify the program reaches its intended ending or exit.
